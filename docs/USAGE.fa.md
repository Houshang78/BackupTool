# راهنمای استفاده

**زبان‌ها:** [English](USAGE.md) · [Deutsch](USAGE.de.md) · فارسی

چگونه به هر روشِ پشتیبانی‌شده پشتیبان بگیریم — انتخاب مسیرها، نادیده‌گرفتن
پوشه‌ها، با یا بدون رمزنگاری، مقایسهٔ افزایشی و بازگردانی. برای هر دو پیاده‌سازی؛
**تفاوت‌های پایتون و راست مشخص شده‌اند**.

- پایتون: `backuptool` (یا `./backuptool-portable`) — مقایسهٔ چک‌سام با **SHA-256**،
  **بدون رمزنگاری**.
- راست: `backuptool` — مقایسهٔ چک‌سام با **BLAKE3**، **رمزنگاری** (`--cipher`).

> در مثال‌ها `backuptool` همان دستور است. با اجراکنندهٔ پرتابلِ پایتون به‌جای آن
> `./backuptool-portable` و با باینریِ تازه‌ساختهٔ راست `./target/release/backuptool`.

---

## ۱. مفاهیم پایه

- **مجموعهٔ پشتیبان** — یک کپیِ نام‌دار از یک سیستم در مقصد. نام با `-s NAME`
  (پیش‌فرض: نام میزبان). چند سیستم می‌توانند یک دیسک را به اشتراک بگذارند:
  ```
  /Volumes/Backup/
    my-laptop/      .backuptool-manifest.json + فایل‌ها
    work-pc/        .backuptool-manifest.json + فایل‌ها
  ```
- **مانیفست** — `<set>/.backuptool-manifest.json` مسیر، اندازه، mtime، حالت و
  uid/gid هر فایل (و در حالت چک‌سام، هش آن) را ذخیره می‌کند. مبنای مقایسهٔ افزایشی
  است و هنگام بازگردانی اجازهٔ بازنشاندن مجوزها را می‌دهد — حتی از exFAT.
- **افزایشی** — فقط موارد تغییر‌یافته/جدید کپی می‌شوند. «تغییر‌یافته» یعنی **اندازه
  یا mtime** فرق کند (پیش‌فرض) یا **چک‌سام** فرق کند (`-c`).

---

## ۲. انتخاب مسیرها

### منابع (چه چیزی پشتیبان گرفته شود)
یک یا چند فایل/پوشه به‌صورت آرگومان:
```bash
backuptool backup ~/Documents ~/Pictures ~/.config -d /Volumes/Backup
```
مسیرها به‌صورت **مطلق** در مجموعه ذخیره می‌شوند: `/home/me/Documents/a.txt` →
`<dest>/<set>/home/me/Documents/a.txt`. (در مک، ریشه‌های symlink مانند `/tmp` به مسیر
واقعی، مثلاً `/private/tmp`، تبدیل می‌شوند.)

### مقصد (`-d`)
دیسک پشتیبان یا یک پوشه؛ در صورت نبودن ساخته می‌شود:
```bash
backuptool backup ~/ -d /Volumes/Backup        # دیسک خارجی
backuptool backup ~/ -d /mnt/nas/backups       # درایو شبکه
```

### نام مجموعه (`-s`)
```bash
backuptool backup ~/ -d /Volumes/Backup -s my-laptop
backuptool list -d /Volumes/Backup             # همهٔ مجموعه‌های روی دیسک
```

### دایرکتوری‌های سیستمی (اجرا با root)
هنگام اجرا با **root** (`sudo`)، دایرکتوری‌های سیستمیِ منتخب **به‌صورت خودکار**
گنجانده می‌شوند: `/etc`، `/usr/local/etc`، `/opt` (در لینوکس به‌علاوهٔ `/srv`،
`/root`، `/var/spool/cron`). با مسیر کامل ذخیره و مانند بقیه به‌صورت افزایشی به‌روز
می‌شوند. کنترل:
```bash
sudo backuptool backup ~/ -d /Volumes/Backup --system     # اجباری (هر کاربر)
backuptool backup ~/ -d /Volumes/Backup --no-system       # هرگز گنجانده نشود
```
فقط ورودی‌های خواندنی گرفته می‌شوند — بدون root بیشترِ `/etc` نادیده می‌ماند.

## ۳. نادیده‌گرفتن پوشه‌ها / فایل‌ها

`-e PATTERN` (چندبار). کش‌ها، سطل زباله و بندانگشتی‌ها به‌صورت پیش‌فرض حذف می‌شوند.
**نحو الگو متفاوت است:**

| | پایتون | راست |
|---|---|---|
| موتور | `fnmatch` روی کل مسیر | `globset` (`**` از پوشه‌ها عبور می‌کند) |
| حذف یک پوشه در همه‌جا | `-e '*/node_modules/*'` | `-e '**/node_modules/**'` |
| بر اساس پسوند | `-e '*.iso'` | `-e '**/*.iso'` |
| یک مسیر | `-e '/home/me/big/*'` | `-e '/home/me/big/**'` |

```bash
# پایتون
backuptool backup ~/ -d /Volumes/Backup -e '*/node_modules/*' -e '*/.git/*' -e '*.iso'
# راست
backuptool backup ~/ -d /Volumes/Backup -e '**/node_modules/**' -e '**/.git/**' -e '**/*.iso'
```
حذف‌های پیش‌فرض (هر دو): `.cache`، سطل زباله، `.thumbnails`، کش مرورگرها،
`lost+found` و بازماندهٔ مک (`.Spotlight-V100`/`.Trashes`/`.fseventsd`؛ راست
`.DS_Store` را هم نادیده می‌گیرد).

## ۴. مقایسهٔ افزایشی

```bash
# سریع (پیش‌فرض): تغییر بر اساس اندازه یا mtime
backuptool backup ~/ -d /Volumes/Backup
# دقیق: تغییر بر اساس هشِ محتوا (همهٔ هسته‌ها)
backuptool backup ~/ -d /Volumes/Backup -c        # پایتون: SHA-256 | راست: BLAKE3
# آینه: در مقصد هم آنچه از منبع حذف شده پاک شود
backuptool backup ~/ -d /Volumes/Backup --delete
# کارگرها (موازی‌سازی)، پیش‌فرض = هسته‌های پردازنده
backuptool backup ~/ -d /Volumes/Backup -j 8
# اجرای آزمایشی: فقط نمایش، بدون نوشتن
backuptool backup ~/ -d /Volumes/Backup -n
```

### لاگ هر اجرا (با تاریخ)
هر پشتیبانِ واقعی یک لاگِ تاریخ‌دار در
`<dest>/<set>/.backuptool-logs/backup-YYYYmmdd-HHMMSS.log` می‌نویسد که **مسیر کامل**
هر فایلِ تغییر‌یافته/جدید (`CHANGED`) و هر فایلِ حذف‌شده (`DELETED`) را به‌همراه سرخط
خلاصه فهرست می‌کند:
```
# backuptool  set=my-laptop  host=server01  2026-06-04T18:13:46
# changed/new=2 unchanged=120 deleted=0 errors=0
CHANGED	/etc/hosts
CHANGED	/home/me/Documents/notes.md
```

## ۵. رمزنگاری — *فقط راست*

رمز را با `--cipher` انتخاب کنید. محتوای هر فایل رمزشده ذخیره می‌شود؛ مانیفست خوانا
می‌ماند (فقط مسیرها/فراداده). کلید با Argon2id از گذرواژه ساخته می‌شود (نمک تصادفی
برای هر مجموعه).
```bash
backuptool backup ~/ -d /Volumes/Backup                          # بدون (پیش‌فرض)
backuptool backup ~/ -d /Volumes/Backup --cipher aes256gcm       # گذرواژه می‌پرسد
backuptool backup ~/ -d /Volumes/Backup --cipher chacha20poly1305
```
غیرتعاملی (خودکارسازی/cron) — گذرواژه از متغیر محیطی:
```bash
BACKUPTOOL_PASSWORD='secret' backuptool backup ~/ -d /Volumes/Backup --cipher aes256gcm
```
> گذرواژه را امن نگه دارید — **بدون آن پشتیبانِ رمزشده قابل بازگردانی نیست.** رمز و
> نمک در مانیفست هستند، پس `restore` خودکار گذرواژه می‌پرسد. نسخهٔ پایتون رمزنگاری
> نمی‌کند.

## ۶. بازگردانی

```bash
# همیشه ابتدا اجرای آزمایشی در یک پوشهٔ موقت (بدون نوشتن)
backuptool restore -S /Volumes/Backup -s my-laptop -t /tmp/restore-test -n
# بازگردانی واقعی در پوشهٔ موقت
backuptool restore -S /Volumes/Backup -s my-laptop -t /tmp/restore-test
# بازگردانی در سیستمِ در حال اجرا (uid/gid نیازمند root)
sudo backuptool restore -S /Volumes/Backup -s my-laptop -t /
```
- `-S` پوشهٔ پشتیبان، `-s` مجموعه، `-t` ریشهٔ مقصد (پیش‌فرض `/`).
- `--no-meta` از بازنشاندن مجوزها/مالک صرف‌نظر می‌کند.
- مجموعهٔ رمزشده: `restore` آن را از مانیفست تشخیص می‌دهد و گذرواژه می‌پرسد
  (یا `BACKUPTOOL_PASSWORD` را می‌خواند).
- مجوزها، مالک (با root) و mtime از مانیفست بازنشانده می‌شوند — همین بازگردانی از
  دیسک **exFAT** را بدون از دست رفتن می‌کند.

> ⚠️ `-t /` سیستمِ در حال اجرا را تغییر می‌دهد. ابتدا با `-n` آزمایش کنید یا در یک
> پوشهٔ موقت بازگردانید.

---

## ۷. exFAT / دیسک‌های چندسکویی

exFAT روی لینوکس، مک و ویندوز خواندنی/نوشتنی است اما مجوزهای یونیکس را ذخیره
نمی‌کند. اینجا مهم نیست: فراداده در مانیفست است و هنگام بازگردانی بازنشانده می‌شود.
symlinkها (که exFAT نمی‌تواند ذخیره کند) در مانیفست ثبت و هنگام بازگردانی روی یک
فایل‌سیستمِ توانمند بازساخته می‌شوند. پس exFAT بهترین گزینه برای پشتیبانی است که
همه‌جا قابل استفاده باشد.

## ۸. رابط گرافیکی

اجرا: ورودیِ منوی *backuptool*، `backuptool gui` (پایتون)، `backuptool-gui` (راست)،
یا `./backuptool-portable` بدون آرگومان (پایتون).

- **انتخاب‌گر زبان** (بالا): English / Deutsch / فارسی. زبان جدید با گذاشتن فایل
  `lang/<code>.json`.
- **برگهٔ پشتیبان:** افزودن منابع، انتخاب مقصد، نام مجموعه و تعداد کارگرها،
  *مقایسهٔ چک‌سام* / *بازتاب حذف‌ها* / *شامل فایل‌های سیستمی*، و (راست) **رمزنگاری**
  از فهرست کشویی به‌همراه گذرواژه. *شروع پشتیبان‌گیری*؛ پیشرفت + لاگ در پایین.
- **برگهٔ بازگردانی** (راست): انتخاب پوشهٔ پشتیبان، *بارگذاری مجموعه‌ها*، انتخاب
  مجموعه، ریشهٔ مقصد، در صورت نیاز *اجرای آزمایشی*، گذرواژه برای مجموعه‌های رمزشده،
  و *شروع بازگردانی*.

## ۹. مرجع کامل خط فرمان

```
backup  SOURCES...  -d DEST  [-s SET] [-c] [-j N] [-e PATTERN ...] [--delete]
                    [--system|--no-system] [-n]
                    [--cipher none|aes256gcm|chacha20poly1305]   (فقط راست)
restore -S SOURCE   [-s SET] [-t TARGET] [-j N] [--no-meta] [-n]
list    -d DEST
```

| سوییچ | معنی |
|---|---|
| `-d` | مقصد / دیسک پشتیبان (backup, list) |
| `-s` | نام مجموعهٔ پشتیبان (پیش‌فرض: نام میزبان) |
| `-c` | مقایسهٔ چک‌سام (SHA-256 پایتون / BLAKE3 راست) |
| `-j N` | کارگرهای موازی (پیش‌فرض: هسته‌های پردازنده) |
| `-e` | الگوی استثنا، چندبار (نحو متفاوت — §۳) |
| `--delete` | بازتاب حذف‌ها در مقصد |
| `--system` / `--no-system` | دایرکتوری‌های سیستمی (/etc و …)؛ خودکار با root |
| `--cipher` | رمزنگاری (فقط راست) |
| `-n` | اجرای آزمایشی |
| `-S` | پوشهٔ پشتیبان (restore) |
| `-t` | ریشهٔ مقصد برای بازگردانی (پیش‌فرض `/`) |
| `--no-meta` | عدم بازنشاندن مجوزها/مالک هنگام بازگردانی |
